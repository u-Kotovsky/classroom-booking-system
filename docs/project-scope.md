# Назначение и границы проекта

Тема курсового проекта: «Разработка системы бронирования учебных аудиторий»  
Название репозитория: `classroom-booking-system`

## 1. Назначение системы

Разрабатываемая программная система предназначена для просмотра доступных учебных аудиторий и создания заявок на бронирование.  
Система обеспечивает учёт аудиторий, временных интервалов и бронирований, а также предотвращение конфликтов расписания.

### Пользователь системы должен иметь возможность:

- просматривать список доступных учебных аудиторий;
- получать информацию об аудитории (вместимость, тип, оборудование);
- просматривать расписание занятости аудитории;
- выбирать временной интервал для бронирования;
- создавать заявку на бронирование;
- просматривать статус своих заявок;
- отменять свою заявку до её подтверждения администратором.

### Администратор системы должен иметь возможность:

- просматривать все заявки на бронирование;
- принимать (подтверждать) заявки на бронирование;
- отклонять заявки на бронирование;
- отменять подтверждённые бронирования;
- добавлять и изменять информацию об аудиториях;
- изменять состояние аудитории (доступна, на ремонте, зарезервирована).

## 2. Основные объекты предметной области

В системе выделены следующие основные сущности:

- пользователь (студент, преподаватель, администратор);
- учебная аудитория;
- заявка на бронирование;
- временной интервал (слот расписания);
- состояние аудитории;
- состояние заявки;
- конфликт расписания.

### Примеры типов аудиторий

- лекционная;
- лабораторная;
- семинарная;
- компьютерный класс.

### Примеры состояний аудитории

- `Available` — доступна для бронирования;
- `Reserved` — зарезервирована (заявка подтверждена);
- `Maintenance` — на обслуживании / ремонте;
- `Unavailable` — временно недоступна.

### Примеры состояний заявки

- `Pending` — ожидает подтверждения администратора;
- `Approved` — подтверждена;
- `Rejected` — отклонена;
- `Cancelled` — отменена пользователем или администратором.

## 3. Границы проекта

### В систему входит

| № | Функция |
|---|---------|
| 1 | Ведение каталога учебных аудиторий |
| 2 | Проверка доступности аудитории на выбранный интервал |
| 3 | Создание заявки на бронирование |
| 4 | Проверка конфликтов расписания |
| 5 | Принятие (подтверждение) заявки администратором |
| 6 | Отклонение заявки администратором |
| 7 | Отмена заявки пользователем или администратором |
| 8 | Изменение состояния аудитории |
| 9 | Просмотр расписания занятости аудитории |
| 10 | Хранение информации о пользователях |
| 11 | Просмотр истории бронирований |

### В систему не входит

В рамках курсового проекта не реализуются:

1. Интеграция с внешними системами расписания (1С, электронный журнал, Google Calendar).
2. Отправка уведомлений по электронной почте, SMS или в мессенджерах.
3. Мобильное приложение (только веб-интерфейс через браузер).
4. Интеграция с системами контроля физического доступа (электронные замки, СКУД).
5. Генерация отчётов и аналитика загрузки аудиторий.
6. Многофилиальность и поддержка нескольких зданий / кампусов.
7. Рекуррентное (повторяющееся) бронирование — например, «каждый понедельник с 9:00 до 10:30».
8. Реальные платежи и финансовые операции.
9. Импорт расписания из внешних источников.

Эти функции могут быть добавлены при дальнейшем развитии проекта.
