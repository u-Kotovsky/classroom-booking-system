## 2. Дефект 1. Поврежденная кодировка строк в интеграционных тестах

### 2.1. Симптом

В файле:

```text
tests/ClassroomBooking.IntegrationTests/BookingScheduleIntegrationTests.cs
```

строки назначения бронирования отображались как поврежденный текст:

```text
"?????? ????"
"?????? ??????"
"??????? ????"
"???????????? ??????"
"???????"
```

Тесты могли выполняться, но данные в тестах были нечитаемы.

### 2.2. Версия / коммит

Текущая revision ветки `fix/stage4-debugging` до исправления.

### 2.3. Условия воспроизведения

1. Открыть файл `BookingScheduleIntegrationTests.cs`.
2. Найти параметр `Purpose` в вызовах `CreateBookingRequest`.
3. Выполнить:

```bash
dotnet test --filter FullyQualifiedName~BookingScheduleIntegrationTests
```

### 2.4. Гипотезы

1. Файл был сохранен не в кодировке UTF-8.
2. Текст был поврежден при копировании из консоли или другого источника.
3. Проблема заключалась не в файле, а в кодировке терминала или редактора.

### 2.5. Инструмент диагностики

- просмотр файла в редакторе с явной кодировкой UTF-8;
- поиск поврежденных последовательностей символов;
- проверка настроек `.editorconfig`;
- запуск тестов до и после исправления файла.

### 2.6. Наблюдаемый факт, подтверждающий первопричину

В исходном файле вместо кириллических символов присутствовали знаки вопроса.

После замены строк на корректные русские значения и сохранения файла в UTF-8 текст отображался правильно:

```csharp
"Учебное занятие"
"Первое занятие"
"Второе занятие"
"Лабораторная работа"
"Семинар"
```

Следовательно, проблема была не только в отображении, но и в поврежденном содержимом исходного файла.

### 2.7. Первопричина

Нарушение кодировки исходного тестового файла.

### 2.8. Исправление

Файл `BookingScheduleIntegrationTests.cs` заменен на версию с корректными строками и явными `using`-директивами.

### 2.9. Регрессионный тест

```bash
dotnet test --filter FullyQualifiedName~BookingScheduleIntegrationTests
```

Ожидаемый результат:

```text
Passed!
```

Дополнительная проверка:

```powershell
Select-String -Path tests/ClassroomBooking.IntegrationTests/BookingScheduleIntegrationTests.cs -Pattern "\?\?\?\?\?\?"
```

Ожидаемый результат: совпадений нет.

### 2.10. Почему симптом отличался от первопричины

Симптом выглядел как проблема отображения или локализации тестовых данных.

Первопричина заключалась в поврежденной кодировке самого исходного файла.

## 3 Дефект 2. Пустой шаблонный тест создавал ложное покрытие

### 3.1. Симптом

В проекте интеграционных тестов присутствовал файл:

```text
tests/ClassroomBooking.IntegrationTests/UnitTest1.cs
```

с пустым тестом:

```csharp
[Fact]
public void Test1()
{
}
```

Команда `dotnet test` показывала этот тест как пройденный, хотя он не проверял никакого поведения.

### 3.2. Версия / коммит

Текущая revision ветки `fix/stage4-debugging` до исправления.

### 3.3. Условия воспроизведения

Выполнить:

```bash
dotnet test --list-tests
```

или:

```bash
dotnet test
```

В списке тестов присутствует `UnitTest1.Test1`.

### 3.4. Гипотезы

1. Это остаток шаблона проекта xUnit.
2. Это временная заглушка, забытая после добавления реальных тестов.
3. Это намеренный smoke-тест, но без проверок он не имеет ценности.

### 3.5. Инструмент диагностики

- `dotnet test --list-tests`;
- анализ содержимого `UnitTest1.cs`;
- сравнение с реальными интеграционными тестами в `BookingScheduleIntegrationTests.cs`.

### 3.6. Наблюдаемый факт, подтверждающий первопричину

Метод `Test1` не содержал вызовов проверяемого кода и не содержал утверждений `Assert`.

Имя класса `UnitTest1` соответствует шаблонному тесту, создаваемому `dotnet new xunit`.

Реальные интеграционные сценарии уже присутствовали в `BookingScheduleIntegrationTests.cs`.

### 3.7. Первопричина

В проекте остался неиспользуемый шаблонный тест.

### 3.8. Исправление

Файл удален:

```bash
git rm tests/ClassroomBooking.IntegrationTests/UnitTest1.cs
```

### 3.9. Регрессионный тест

```bash
dotnet test --list-tests
```

Ожидаемый результат:

```text
UnitTest1.Test1 отсутствует в списке тестов.
```

Затем:

```bash
dotnet test
```

Ожидаемый результат: все реальные тесты проходят.

### 3.10. Почему симптом отличался от первопричины

Симптом был положительным: тест проходил.

Первопричина была негативной: тест не проверял поведение и создавал ложное ощущение покрытия.
