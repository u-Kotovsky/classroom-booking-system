# ADR-002. Взаимодействие через контракты

## Статус
Принято.

## Проблема
Прямое обращение модуля к внутренним классам другого модуля
увеличивает связанность приложения.

## Решение
Взаимодействие модулей выполняется через публичные интерфейсы и DTO:

    BookingModule → IScheduleConflictService → ScheduleModule

## Последствия
Положительные: слабая связанность, простота тестирования,
контролируемое изменение контрактов.
Отрицательные: необходимость поддерживать дополнительные
интерфейсы и DTO.
