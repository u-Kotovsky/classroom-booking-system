# ADR-001. Использование модульной архитектуры

## Статус
Принято.

## Проблема
Необходимо разделить функции системы так, чтобы изменение логики
расписания не приводило к изменению модуля аудиторий или пользователей.

## Решение
Разделить приложение на функциональные модули:
Classrooms, Bookings, Schedule, Users.

## Причина
Разделение позволяет определить ответственность компонентов,
уменьшить связанность, независимо тестировать бизнес-логику
и упростить расширение проекта.
